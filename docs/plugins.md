# Плагины sonar: руководство автора

Плагин — это папка с описанием `plugin.json` и программой. sonar запускает программу и разговаривает с ней строками JSON
через стандартный ввод и вывод. Программу можно написать на чём угодно: Python, Go, Node, готовый exe.

Плагины бывают четырёх видов (`kind`):

| Вид | Что делает |
|---|---|
| `source` (источник) | узнаёт ссылки сайта, показывает страницы треков, альбомов, плейлистов и исполнителей, ищет |
| `downloader` (загрузчик) | получает трек и кладёт файл на диск |
| `tagger` (теггер) | отвечает значениями тегов (жанр, текст, …), которые sonar запишет в файл |
| `tool` (утилита) | зарезервирован под следующий проект; sonar пока только показывает такой плагин в списке |

Готовые шаблоны лежат в `plugins/templates/`: на Python (только стандартная библиотека) и на Go, по одному на источник, загрузчик и теггер.
Встроенные плагины (`cmd/plugins/*`: spotify, amazon, lucida, doubledouble, chosic) — рабочие примеры на Go.

## Что делает sonar, а что — плагин

sonar делает сам, плагину этого не нужно:

- **очередь** загрузок, её сохранение между запусками, повторы, отмена;
- **имена файлов и папок** по шаблонам из настроек: плагин получает готовый путь без расширения;
- **теги и обложку**: после загрузки sonar дописывает основные теги (название, исполнитель, исполнитель альбома, альбом, номер трека и диска,
  дата, ISRC, обложка) **только в пустые поля**; теги, которые уже есть в файле от загрузчика, он не трогает.
  Потом поверх пишут теггеры, по порядку списка на странице «Плагины» (кто ниже в списке, тот побеждает). Сбой теггера загрузку не ломает;
  sonar ждёт теггеры не дольше 20 секунд от начала загрузки;
- **конвертацию** в MP3 или M4A через FFmpeg, если пользователь выбрал такой формат;
- **сопоставление** треков между сервисами (например, трек Spotify → трек Amazon), окно выбора кандидата;
- **лимит запросов к сайту**: счётчик треков, предупреждение, паузу. Лимит плагин только описывает в `downloader.guard`;
- **прокси** пользователя: плагин получает уже выбранный адрес;
- **перезапуск** упавшего плагина (не чаще раза в 10 секунд) и остановку плагинов при выходе из sonar.

Плагин только **отвечает на вызовы**: «вот страница по ссылке», «вот результаты поиска», «скачай этот трек сюда», «вот теги».
Что плагин делает внутри (сайт, свой скрипт, локальная программа), sonar не волнует.

## Папка и `plugin.json`

```
my-plugin/
  plugin.json     описание (обязательно)
  main.py         программа: любой файл или exe, на который указывает run
  ...             всё остальное, что нужно плагину
```

Все плагины лежат в папке `plugins` рядом с `sonar.exe`, по одной подпапке на плагин:

- `plugins\official` — официальные, приходят с sonar. Если такую папку удалить или испортить, кнопка
  **Синхронизировать официальные** скачает с GitHub (`plugins.zip` из релиза той же версии) и вернёт её;
  ставится только копия, чьи файлы совпали с контрольной суммой в `sonar.exe`;
- `plugins\custom` — ваши: сюда ставит «Установить из файла…» и сюда же можно положить папку вручную.

Плагины из старых мест (`%LOCALAPPDATA%\Sonar\plugins` и прямо из `plugins\<id>`) sonar при запуске переносит сюда сам.

Данные плагина (кэши, токены) надо хранить в папке, которую sonar передаёт в `initialize` (`dataDir`): `<папка данных sonar>\plugins-data\<id>`.
Она общая для всех копий плагина с одним `id`, переживает обновление плагина и не входит в экспорт.
Всё, что плагин пишет во время работы, держите в `dataDir`, а не в своей папке: любое изменение папки плагина меняет его контрольную сумму,
и плагин перестаёт считаться доверенным. Поэтому sonar запускает плагины с `PYTHONDONTWRITEBYTECODE=1`, чтобы Python не создавал `__pycache__`.

`plugin.json` в UTF-8. Если описание битое, плагин виден в списке с причиной и не включается.

### Общие поля

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | **обязательно.** Строчные латинские буквы, цифры и дефис, 1–40 знаков, начинается с буквы или цифры (`^[a-z0-9][a-z0-9-]{0,39}$`). Имена устройств Windows (`con`, `nul`, `com1`, …) нельзя |
| `name` | строка | название в списке |
| `version` | строка | **обязательно.** `X.Y.Z`, числа сравниваются как числа |
| `author`, `description` | строка | показываются в списке |
| `kind` | строка | **обязательно.** `source`, `downloader`, `tagger` или `tool` |
| `run` | массив строк | **обязательно.** Чем запускать. Первый элемент — программа, дальше аргументы: `["python", "main.py"]`, `["node", "index.js"]`, `["my-plugin"]`. Нет `python` в `PATH` — замените его на `py` или полный путь к `python.exe`. Если файл с таким именем есть в папке плагина, берётся он (на Windows к имени дописывается `.exe`), иначе программа ищется в `PATH`. Рабочая папка — папка плагина |
| `contract` | число | версия контракта; сейчас **1**. Пропущено — считается 1. Другое число — плагин не включится |
| `settings` | массив | поля настроек, см. ниже |
| `source` / `downloader` / `tagger` | объект | блок вида; обязателен для своего `kind` |

Тексты (`label`, `hint` и подписи вариантов в `options`) можно писать строкой (это английский) или по языкам: `{"en": "Base URL", "ru": "Базовый адрес"}`.
Если нужного языка нет, берётся английский, а за ним первый по алфавиту.

### Настройки (`settings`)

Каждое поле показывается на карточке плагина на странице «Настройки → Плагины». Значения хранит sonar и передаёт плагину
в `initialize` (поле `settings`, объект «`key` → значение») и в каждом `$/settings`.

| Поле | Описание |
|---|---|
| `key` | имя значения. Ключи, которые начинаются с `$`, занимает sonar (`$guardLimit`, `$guardWait`): свои так не называйте, чужие игнорируйте |
| `type` | `text` (строка), `number` (число), `switch` (true/false), `select` (один из `options`), `button` (кнопка), `note` (строка-пояснение) |
| `label`, `hint` | подпись и подсказка |
| `default` | значение по умолчанию; пока пользователь ничего не менял, плагин получает его |
| `options` | для `select`: `[{"value": 30, "label": "30 мин"}, …]` |
| `action` | для `button` обязательно: имя действия, которое придёт плагину запросом `action` |

### Источник (`source`)

```json
"source": {
  "service": "example",
  "label": "Example",
  "icon": "",
  "links": ["https://example\\.com/track/[0-9]+"],
  "can": ["metadata", "search", "parseLink"]
}
```

- `service` — короткое имя сервиса (`spotify`, `amazon`, `example`). Оно же стоит в поле `service` ответов плагина и в треках, которые приходят загрузчикам.
- `label` — подпись во вкладках поиска и сообщениях; `icon` — адрес картинки (пустая строка — значок по умолчанию).
- `links` — регулярные выражения (синтаксис Go, RE2) для ссылок, которые узнаёт плагин. **Выражение должно подойти ко всей вставленной ссылке:**
  sonar сам оборачивает его в `^(?:…)$`. Хотите узнавать любую ссылку с этим началом — допишите `.*` сами:
  `https://example\\.com/.*`. Не забудьте экранировать точку и обратную косую в JSON (`\\.`). Выражение, которое не компилируется,
  попадает в журнал и ни к чему не подходит. Одну и ту же ссылку узнали два источника — её открывает тот, что выше в списке плагинов.
- `can` — что плагин умеет; sonar не зовёт то, чего в списке нет:

| `can` | метод | для чего |
|---|---|---|
| `metadata` | `source.metadata` | страница по ссылке |
| `search` | `source.search` | общий поиск |
| `searchByType` | `source.searchByType` | постраничный поиск одного типа («ещё») |
| `find` | `source.find` | кандидаты для сопоставления с треком другого сервиса |
| `tracks` | `source.tracks` | данные треков по ID (с ISRC и длительностью) |
| `album` | `source.album` | альбом с треками (для сопоставления целого альбома) |
| `isrc` | `source.isrc` | поиск треков по ISRC |
| `preview` | `source.preview` | ссылка на 30-секундный фрагмент |
| `parseLink` | `source.parseLink` | вид и ID по ссылке |

Выключенный источник выключен везде: sonar не зовёт его ни для ссылок, ни для поиска, ни для сопоставления.

### Загрузчик (`downloader`)

```json
"downloader": {
  "accepts": "any",
  "parallel": 1,
  "guard": { "limit": 50, "waits": [15, 30, 60, 120], "wait": 30 }
}
```

- `accepts` — треки какого сервиса он берёт: `"amazon"` — только когда sonar нашёл ID трека на Amazon (при необходимости сам сопоставит),
  `"any"` — любой трек сразу, без сопоставления.
- `parallel` — сколько треков качать одновременно (по умолчанию 1).
- `guard` — необязательный лимит: после `limit` треков sonar предупреждает, что сайт может заблокировать, и предлагает паузу из `waits` (минуты),
  по умолчанию `wait`. Счётчик свой у каждого загрузчика. Нет `guard` — нет лимита. Пользователь меняет лимит и паузу на карточке плагина.
- В режиме «Авто» трек получает первый подходящий свободный загрузчик по порядку списка на странице «Плагины».

### Теггер (`tagger`)

```json
"tagger": { "fields": ["genre"], "needs": "spotify" }
```

- `fields` — какие поля плагин заполняет (для списка и людей; sonar записывает всё, что пришло в ответе);
- `needs` — ID какого сервиса ему нужен (`""` — никакого). sonar находит этот ID заранее (по ISRC через источники) и кладёт в `ids`.

Известные имена тегов: `title`, `artist`, `album_artist`, `album`, `track`, `disc`, `date`, `isrc`, `genre`, `lyrics`
и `cover` (адрес картинки: она заменяет обложку файла). Остальные имена пишутся в файл как есть.

## Протокол

Сообщение — один JSON-объект в одной строке (JSON-RPC 2.0, без заголовков и без переносов внутри объекта), в кодировке UTF-8.

- **stdin** плагина: запросы и уведомления от sonar. Закрытие stdin значит «sonar завершился»: выходите. Если плагин не выходит, sonar убивает процесс (на Windows вместе с его дочерними процессами).
- **stdout**: ответы и уведомления плагина. **Ничего, кроме протокола, в stdout печатать нельзя.** Длина строки — до 64 МиБ.
- **stderr**: журнал плагина. Каждая строка попадает в журнал sonar (страница отладки) с именем плагина. Последние строки показываются в причине сбоя.

**В каждом сообщении, и в ваших тоже, обязательно поле `"jsonrpc":"2.0"`.** Строка без него молча отбрасывается: плагин не получит `initialize`
(или sonar не получит ответ) и через 10 секунд будет убит по таймауту.

Четыре вида сообщений:

- запрос: есть `id`, ждёт ответ;
- ответ: тот же `id` и `result`;
- ошибка вместо ответа: тот же `id` и `error`;
- уведомление: `id` нет, ответа нет.

```json
{"jsonrpc":"2.0","id":3,"method":"source.search","params":{"query":"daft punk","limit":10}}
{"jsonrpc":"2.0","id":3,"result":{"tracks":[],"albums":[],"artists":[],"playlists":[]}}
{"jsonrpc":"2.0","id":3,"error":{"code":-32001,"message":"site is down"}}
{"jsonrpc":"2.0","method":"$/progress","params":{"id":5,"bytes":1024,"size":4096,"status":""}}
```

Запросы идут параллельно: ответ на `id` может прийти в любом порядке, поэтому обрабатывайте запросы в отдельных потоках
(длинная загрузка не должна задерживать остальные запросы и `$/cancel`). `initialize` и уведомления sonar шлёт по порядку.

### Жизнь процесса

sonar запускает программу, когда плагин нужен впервые, и держит её, пока плагин включён. Первым сообщением всегда идёт `initialize`.
Плагин отвечает на него (содержимое ответа sonar не использует, можно `{}`) в течение **10 секунд**, иначе его убивают.
Если процесс упал или завис, sonar перезапускает его при следующем вызове, не чаще раза в 10 секунд, а сбой показывает в списке плагинов
и в ошибке трека. Загрузка, от которой больше 60 секунд нет ни одного `$/progress`, считается зависшей. Ограничения по времени
для остальных вызовов sonar ставит сам (от 30 секунд до нескольких минут): отвечайте быстро или хотя бы без зависаний.

### Коды ошибок

| Код | Значение | Что делает sonar |
|---|---|---|
| `-32001` | сайт недоступен или отказывает | ставит загрузчик на паузу и пробует другой |
| `-32002` | нужно действие пользователя | показывает `data.message` и кнопку действия `data.action` (имя поля `button` из `settings`) |
| `-32000` | любая другая ошибка | обычная ошибка трека, текст `message` виден пользователю |
| `-32601` | метода нет | так отвечайте на неизвестный метод |

Данные для `-32002`: `"data": {"message": "Нужна проверка в браузере", "action": "check"}`. Ошибка с любым другим кодом считается `-32000`.
Если плагин не ответил или упал, sonar сам считает сайт недоступным (как `-32001`).

### Метод `initialize`

Запрос. Те же параметры (полная структура `InitParams`) приходят потом в каждом уведомлении `$/settings`.

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
  "contract":1,
  "lang":"ru",
  "settings":{"baseUrl":"http://localhost:8000"},
  "dataDir":"C:\\Users\\me\\AppData\\Roaming\\sonar\\plugins-data\\example-downloader",
  "proxy":"",
  "effectiveProxy":"http://127.0.0.1:10808"}}
```

Ответ: `{"jsonrpc":"2.0","id":1,"result":{}}`.

- `settings` — значения настроек (с уже подставленными `default`);
- `proxy` — прокси, как его ввёл пользователь в настройках sonar (`""` — не задан);
- `effectiveProxy` — прокси, которым sonar сам ходил бы на `https://example.com` с учётом настроек, переменных окружения и системы (`""` — напрямую).
  Ходите в сеть через него. Адреса `localhost` и `127.0.0.1` sonar всегда открывает напрямую;
- `lang` — язык интерфейса (`ru`, `en`, …); `dataDir` — папка для файлов плагина (sonar уже создал её).

Плагин на Go берёт готовое: `sdk.Server.FollowProxy` настраивает общий HTTP-клиент `internal/httpx` под прокси.

### Уведомление `$/settings` (от sonar)

Приходит при любой смене настроек плагина или прокси. Содержимое — **полный `InitParams`**, такой же, как у `initialize`.
Применяйте все поля заново, а не только то, что, как вам кажется, изменилось.

### Уведомление `$/progress` (от плагина)

Только для идущего запроса `download`. `id` — номер запроса, `bytes` — сколько байт уже записано, `size` — сколько ждать всего (0, если неизвестно),
`status` — короткая строка для полоски загрузки (можно пустую). Сообщение только со `status` (без `bytes` и `size`) полоску не сбрасывает,
но считается признаком жизни, как и любое другое `$/progress`: каждое такое уведомление обнуляет 60-секундный счётчик зависания.
Присылайте его не реже чем раз в несколько секунд. Если этап долгий и молчаливый (запросы к сайту до начала скачивания, ожидание
в очереди сайта), всё равно шлите `$/progress` хотя бы раз в 20–30 секунд: повторите последние `bytes`, `size` и `status` или пришлите нули
с пустым `status` — полоска от этого не сбросится (так делает шаблон на Python).
Плагины на Go с `internal/plugin/sdk` делают это сами: SDK повторяет последний `$/progress` каждые 20 секунд, пока идёт `download`.

```json
{"jsonrpc":"2.0","method":"$/progress","params":{"id":5,"bytes":524288,"size":3145728,"status":""}}
```

### Уведомление `$/cancel` (от sonar)

Пользователь отменил загрузку: прекратите работу над запросом `id` и ответьте на него ошибкой (любой). При выходе из sonar, выключении плагина
и перезапуске `$/cancel` не шлют: процесс просто убивается.

```json
{"jsonrpc":"2.0","method":"$/cancel","params":{"id":5}}
```

### Уведомление `$/status` (от плагина)

Загрузчик может сам сообщить, что готов или что ему нужно действие пользователя (например, проверка в браузере), не дожидаясь запроса.

```json
{"jsonrpc":"2.0","method":"$/status","params":{"available":false,"needsAction":{"message":"Нужна проверка в браузере","action":"check"}}}
{"jsonrpc":"2.0","method":"$/status","params":{"available":true}}
```

`needsAction` ставит загрузчик на паузу с кнопкой; `available: true` снимает.

### Метод `action`

Пользователь нажал кнопку `button` из `settings`. Запрос: `{"name": "check"}` (значение `action` поля). Ответ: `{}`. Можно работать долго (до 10 минут):
например, открыть окно браузера и ждать пользователя. Ошибка с текстом покажется пользователю.

```json
{"jsonrpc":"2.0","id":7,"method":"action","params":{"name":"check"}}
{"jsonrpc":"2.0","id":7,"result":{}}
```

### Методы загрузчика

**`download`** — скачать трек.

```json
{"jsonrpc":"2.0","id":5,"method":"download","params":{
  "track":{"id":"2Foc5Q5nqNiosCNqttzHof","title":"Get Lucky","artist":"Daft Punk","album":"Random Access Memories",
           "album_artist":"Daft Punk","release_date":"2013-05-17","track_number":8,"disc_number":1,
           "service":"spotify","duration_ms":369000,"explicit":false,"isrc":"USQX91300108","image":"https://…"},
  "ids":{"spotify":"2Foc5Q5nqNiosCNqttzHof","amazon":"B00A3SGXAA"},
  "pathNoExt":"C:\\Users\\me\\Music\\sonar\\Daft Punk\\Random Access Memories\\08 - Get Lucky"}}
{"jsonrpc":"2.0","id":5,"result":{"path":"C:\\Users\\me\\Music\\sonar\\Daft Punk\\Random Access Memories\\08 - Get Lucky.flac"}}
```

- `track` — данные трека. `service` — сервис, откуда трек (пусто значит `amazon`).
- `ids` — «сервис → ID трека на нём». Всегда есть собственный сервис трека; для `accepts: "amazon"` гарантирован `ids.amazon`.
- `pathNoExt` — путь будущего файла **без расширения**. Папки для файла на всякий случай создайте сами.
  Файл пишите рядом: `pathNoExt + ".flac"`.
- В ответе — полный путь готового файла. Формат sonar определяет по расширению: `.flac`, `.mp3` или `.m4a`. Файл уже в нужном формате
  не конвертируется. Путь должен быть абсолютным, вести к обычному файлу (не папке) и лежать в той же папке, что и `pathNoExt`;
  иначе sonar считает загрузку этого трека неудачной (обычная ошибка трека, загрузчик на паузу не встаёт). Пишите во временный файл и переименовывайте в конце, чтобы половинка файла не осталась в папке.
- Пока идёт загрузка, шлите `$/progress`; на `$/cancel` останавливайтесь.
- Ошибки: `-32001`, если сайт лёг (sonar попробует другой загрузчик), `-32002`, если нужно действие пользователя,
  `-32000`, если не получилось именно с этим треком (например, файла нет на сайте: такой трек не стоит отдавать другому сайту зря).

### Методы источника

Все методы источника отвечают данными в формате `internal/model` (`internal/model/model.go`). Поле `service` везде равно `source.service`
из `plugin.json`. Пустые списки отдавайте как `[]`, а не `null`.

**`source.metadata`** `{url}` — страница по ссылке. Ответ — объект одной из четырёх форм, по виду ссылки:

```json
{"jsonrpc":"2.0","id":2,"method":"source.metadata","params":{"url":"https://example.com/track/1"}}
{"jsonrpc":"2.0","id":2,"result":{"service":"example","track":{
  "service":"example","id":"1","name":"Example Song","artists":"Example Artist","album_name":"Example Album",
  "album_id":"10","duration_ms":180000,"images":"https://…/cover.jpg","release_date":"2024-01-01",
  "track_number":1,"external_urls":"https://example.com/track/1"}}}
```

| Ссылка | Форма ответа |
|---|---|
| трек | `{"service", "track": {…}}` |
| альбом | `{"service", "album_info": {"name","artists","images","release_date","total_tracks","external_urls"}, "track_list": [трек, …]}` |
| плейлист | `{"service", "playlist_info": {"owner","cover","description","tracks":{"total"},"followers":{"total"},"external_urls"}, "track_list": […]}` |
| исполнитель | `{"service", "artist_info": {"name","images","followers","external_urls","discography_type","total_albums"}, "album_list": […], "track_list": […], "top_tracks": […]}` |

Элемент `track_list` — тот же трек, что и в `track`, плюс необязательные `album_type`, `status`. Подробные списки полей — в `internal/model/model.go`.
`images` — адрес картинки строкой.

**`source.search`** `{query, limit}` → по списку на каждый вид:

```json
{"jsonrpc":"2.0","id":3,"result":{"tracks":[{"id":"1","name":"Example Song","type":"track","artists":"Example Artist","images":"","external_urls":"https://example.com/track/1"}],"albums":[],"artists":[],"playlists":[]}}
```

Элемент: `id`, `name`, `type` (`track`, `album`, `artist` или `playlist`), `artists`, `album_name`, `images`, `release_date`, `external_urls`, `duration_ms`, `total_tracks`, `owner`, `is_explicit`.

**`source.searchByType`** `{query, type, limit, offset}` → массив элементов того же вида, что в `source.search`, но одного `type` (`track`, `album`, `artist` или `playlist`):

```json
{"jsonrpc":"2.0","id":4,"method":"source.searchByType","params":{"query":"daft punk","type":"album","limit":50,"offset":50}}
{"jsonrpc":"2.0","id":4,"result":[{"id":"10","name":"Random Access Memories","type":"album","artists":"Daft Punk","images":"https://…/cover.jpg","release_date":"2013-05-17","external_urls":"https://example.com/album/10","total_tracks":13}]}
```

**`source.parseLink`** `{url}` → `{"kind","id"}` (`kind`: `track`, `album`, `playlist`, `artist`):

```json
{"jsonrpc":"2.0","id":5,"method":"source.parseLink","params":{"url":"https://example.com/track/1"}}
{"jsonrpc":"2.0","id":5,"result":{"kind":"track","id":"1"}}
```

**`source.find`** `{query}` → кандидаты для сопоставления с треком другого сервиса: массив элементов `kind` (`track` или `album`), `id`, `album_id`, `title`, `artist`, `image`, `url`, `explicit`.
Очки и порядок sonar считает сам.

```json
{"jsonrpc":"2.0","id":6,"method":"source.find","params":{"query":"Get Lucky Daft Punk"}}
{"jsonrpc":"2.0","id":6,"result":[{"kind":"track","id":"B00A3SGXAA","album_id":"B00A3SGX00","title":"Get Lucky","artist":"Daft Punk","image":"https://…/cover.jpg","url":"https://example.com/track/B00A3SGXAA","explicit":false}]}
```

**`source.tracks`** `{ids}` → массив данных треков (для сопоставления: ISRC и длительность):

```json
{"jsonrpc":"2.0","id":7,"method":"source.tracks","params":{"ids":["B00A3SGXAA"]}}
{"jsonrpc":"2.0","id":7,"result":[{"id":"B00A3SGXAA","title":"Get Lucky","artist":"Daft Punk","album":"Random Access Memories","album_id":"B00A3SGX00","image":"https://…/cover.jpg","release_date":"2013-05-17","isrc":"USQX91300108","duration_ms":369000,"track_number":8,"disc_number":1,"explicit":false}]}
```

**`source.album`** `{id}` → альбом: `id`, `title`, `artist`, `image`, `release_date`, `explicit` и `tracks` (массив в формате `source.tracks`):

```json
{"jsonrpc":"2.0","id":8,"method":"source.album","params":{"id":"B00A3SGX00"}}
{"jsonrpc":"2.0","id":8,"result":{"id":"B00A3SGX00","title":"Random Access Memories","artist":"Daft Punk","image":"https://…/cover.jpg","release_date":"2013-05-17","explicit":false,"tracks":[{"id":"B00A3SGXAA","title":"Get Lucky","artist":"Daft Punk","album":"Random Access Memories","album_id":"B00A3SGX00","isrc":"USQX91300108","duration_ms":369000,"track_number":8,"disc_number":1,"explicit":false}]}}
```

**`source.isrc`** `{isrc}` → массив ID треков с таким ISRC (пустой массив `[]`, если таких нет):

```json
{"jsonrpc":"2.0","id":9,"method":"source.isrc","params":{"isrc":"USQX91300108"}}
{"jsonrpc":"2.0","id":9,"result":["2Foc5Q5nqNiosCNqttzHof"]}
```

**`source.preview`** `{id}` → адрес фрагмента строкой (`""`, если нет):

```json
{"jsonrpc":"2.0","id":10,"method":"source.preview","params":{"id":"1"}}
{"jsonrpc":"2.0","id":10,"result":"https://example.com/preview/1.mp3"}
```

### Метод теггера

**`tag`** `{track, ids}` → `{"fields": {имя тега → значение}}`. `track` и `ids` — как у `download`; `ids` содержит `needs`, если он задан.

```json
{"jsonrpc":"2.0","id":9,"method":"tag","params":{"track":{"title":"Get Lucky","artist":"Daft Punk"},"ids":{"spotify":"2Foc5Q5nqNiosCNqttzHof"}}}
{"jsonrpc":"2.0","id":9,"result":{"fields":{"genre":"Electronic; Disco"}}}
```

Нет данных — отвечайте `{"fields": {}}`. Пустое значение ничего не стирает.

## Установка, экспорт, импорт

Всё это на странице **Настройки → Плагины**.

- **Установить из файла…** принимает zip с плагином: `plugin.json` лежит в корне архива или в единственной папке верхнего уровня.
  Архив распаковывается в `plugins\custom\<id>` (не больше 300 МБ, пути наружу и необычные записи отклоняются).
  Плагин с тем же `id` уже стоит — sonar спросит, заменить ли.
- Можно просто скопировать папку плагина в `plugins\custom` (кнопка **Открыть папку плагинов**) и нажать **Обновить список**.
- **Экспортировать все…** собирает один zip: все плагины, поставленные пользователем (сторонние и обновлённые встроенные), и состояние плагинов:
  включён ли, порядок и настройки. Неизменённые встроенные в архив не попадают: они приходят с sonar (но их состояние сохраняется).
  Папки данных плагинов (`plugins-data`) в экспорт не входят: там токены и кэши.
- **Импортировать…** ставит всё из такого zip в ту же папку и применяет состояние. Если какие-то `id` уже установлены, sonar один раз спрашивает:
  заменить все или пропустить совпадающие.
- **Один `id` в двух папках.** Работает копия с большей версией; при равной версии — копия из `plugins\custom`. Остальные копии в списке помечены
  «заменён версией X». Обновить встроенный плагин — установить его новую версию из zip; «Удалить» у такой копии возвращает встроенную.

### Доверие

Встроенным считается плагин, чьи файлы совпадают с контрольными суммами, зашитыми в `sonar.exe`. Всё остальное — **сторонний плагин**:
плагин с правами пользователя может делать на компьютере что угодно, поэтому перед включением sonar показывает предупреждение
и включает его только после подтверждения. Это касается и плагина из импорта (одно предупреждение на весь импорт, со списком),
и **пользовательской копии встроенного `id`** (например, новой версии lucida из zip): она остаётся выключенной, пока пользователь её не подтвердит.
Подтверждение запоминается для **точного содержимого папки**: изменили любой файл плагина — предупреждение появится снова.

## Как писать и отлаживать

1. Скопируйте шаблон из `plugins/templates/python/<вид>` (или `go/<вид>`) в `plugins\custom\<имя>`, поменяйте `id` и `name` в `plugin.json`.
2. Нажмите «Обновить список» и включите плагин (подтвердите предупреждение). После правки `plugin.json` или файлов снова «Обновить список»:
   sonar перезапустит процесс.
3. Смотрите журнал на странице отладки: туда попадает stderr плагина и сообщения об ошибках запуска.
4. Проверить плагин без sonar можно руками: запустите программу и вводите строки из примеров выше, например
   `{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"contract":1,"settings":{}}}`.
5. Для загрузчика на Python локальный сервер файлов — `python -m http.server`: положите файл `Исполнитель - Название.flac` в его папку,
   в настройках плагина укажите `http://localhost:8000`.

Шаблоны на Go используют тот же SDK (`sonar/internal/plugin/sdk`), что и встроенные плагины. Пакеты `internal` видны только внутри модуля sonar,
поэтому Go-плагин собирают в репозитории: `go build -o example-go-downloader.exe ./plugins/templates/go/downloader`, затем кладут `.exe` и `plugin.json`
в одну папку плагина. Вне репозитория проще писать на Python или реализовать протокол из этого файла самому: он короткий.

Служебный код (чтение строк, потоки, `$/cancel`, `$/settings`, ошибки) скопирован в каждый шаблон нарочно: так каждый шаблон самодостаточен,
его можно взять одним и отдать нейронке без остальных.

Шаблон загрузчика на Python — рабочий «сторонний плагин»: качает `{baseUrl}/{исполнитель} - {название}.flac` через `urllib`, учитывает `effectiveProxy`,
шлёт `$/progress` каждые 256 КиБ и понимает `$/cancel`. Шаблоны источника и теггера отвечают заготовленными данными, а в комментариях сказано, что заменить.

## Как попросить нейронку написать плагин

Дайте нейронке этот файл и шаблон нужного вида, скажите, какой сайт или программу подключить. Пример запроса:

```text
Напиши плагин для sonar (приложение для скачивания музыки). Контракт плагинов описан в приложенном файле docs/plugins.md,
рабочий пример — приложенные plugin.json и main.py из plugins/templates/python/downloader.

Задача: плагин-загрузчик, который <опиши: скачивает трек с сайта … / запускает программу … / берёт файл из папки …>.
Что у меня есть: <адрес сайта, пример запроса и ответа, документация, пример команды>.

Требования:
- только стандартная библиотека Python 3, без pip;
- в stdout только строки протокола JSON-RPC, всё остальное в stderr;
- ходи в сеть через effectiveProxy из initialize и $/settings;
- шли $/progress во время загрузки, останавливайся на $/cancel;
- ошибки: -32001, если сайт недоступен, -32000, если не нашлось именно этого трека;
- настройки (<перечисли, например адрес сервера, логин>) объяви в plugin.json как settings и читай из initialize.

Отдай два файла целиком: plugin.json и main.py.
```

Получите файлы — положите их в папку плагина (см. выше), включите и проверьте на одном треке, глядя в журнал отладки.
